## 1. 系统模块划分

```
[上位机 Python]                      [FPGA  xc7a35tfgg484-2  @50MHz]
┌────────────────────┐   UART(USB转串口)   ┌──────────────────────────────┐
│ host_gui.py 画板   │ ── 帧(791B) ───────▶ │ uart_rx  →  frame_decode     │
│ 28×28 黑底白字      │                      │   ↓ (784×uint8 像素缓冲)      │
│ 重心居中+归一化     │                      │ nn_top (HLS 定点推理核)        │
│ frame.py 组帧+CRC16 │                      │   ↓ (argmax 0..9)            │
│ bench.py 计时       │ ◀── 结果(1B) ────── │ seg_display + led[3:0]       │
└────────────────────┘                      │   → 数码管(最右位)+LED         │
                                            │ uart_tx  ← 回传类别           │
                                            └──────────────────────────────┘
```

- 全部控制逻辑在手写 RTL（`rtl/`），推理在 HLS IP（`hls/nn_accel/`），二者通过简单握手接口对接（像素缓冲 + 启动/完成信号）。

## 2. 帧协议（自定义，报告需说明设计理由）

| 字段 | 长度 | 说明 |
|---|---|---|
| 帧头 | 2B | `0xA5 0x5A`，重同步锚点 |
| 长度 | 2B | payload 字节数 = 784（小端） |
| 序号 | 1B | 帧序号 0..255 回绕（丢包检测） |
| 图像 | 784B | 28×28，行优先，每字节一个像素（0..255，黑底白字） |
| CRC16 | 2B | CCITT，覆盖 [长度..图像]（小端） |
| **合计** | **791B** | |

- **回传**：FPGA 识别后回 1 字节类别（0..9）；错帧回 `0xEE` 后继续等待新帧头。
- 理由：帧头+长度+CRC16 满足 G8 健壮性（错包/乱码可丢弃并重同步）；序号用于上位机检测丢帧。
- **[待评审]** 是否简化（如去掉序号、CRC 换 8bit 校验和）。

## 3. 预处理（重心居中，已知坑 #1）

- 在上位机 Python 做：把笔迹的**灰度质心平移到 28×28 画布中心**，再按 MNIST 分布归一化。
- 理由：训练集 MNIST 数字大致居中；现场手写位置随机，不居中会导致激活分布偏移、识别率崩（无法现场补救）。放上位机最简单，FPGA 只吃已居中的图。

## 4. 网络结构（已定版：训练中验证 test acc ≥ 99%）

| 层 | 输出尺寸 | 参数 |
|---|---|---|
| 输入 | 28×28×1 | uint8 → 标准化 (x/255-0.1307)/0.3081 → 定点 LUT |
| Conv1 | 26×26×16 | 3×3, valid, 16 通道, ReLU |
| MaxPool1 | 13×13×16 | 2×2 |
| Conv2 | 11×11×32 | 3×3, valid, 32 通道, ReLU |
| MaxPool2 | 5×5×32 | 2×2 |
| Flatten | 800 | 5×5×32 |
| FC1 | 64 | 800→64, ReLU |
| FC2 | 10 | 64→10 (logits) |

- **MAC 总量 ≈ 706,752**（Conv1 97,344 + Conv2 557,568 + FC1 51,200 + FC2 640），参数量 56,714。
- 输入标准化用 **256 项 LUT**（`INPUT_LUT`，p → int8）在 FPGA 侧零成本等价实现。
- 理由：8/16 窄网在 98.5% 平台化（无 BN、/255 输入）；加宽到 16/32/64 并标准归一化后 test acc 稳定 ≥99%。

## 5. 量化方案（int8 定点）

- 权重 int8、激活 int8、累加 **int32**；卷积单输出最多 72 项 int8×int8 累加（<2^31，安全）。
- 每层 **per-tensor 2 的幂 scale**（移位实现 requant，不额外占乘法器），round-half-away-from-zero（与 C 的 `(x + (1<<(s-1))) >> s` 一致）。
- 流程：训练浮点 → 逐层校准 scale（min/max 或 MSE）→ Python 定点仿真（纯 numpy 循环，与 C 同构）→ 精度损失 <1% 达标。
- 权重导出 `hls/nn_accel/weights.h`（`const int8_t W[...]`）；测试向量 `testdata/vec_in.bin`/`vec_ref.bin` 作为 Python↔HLS 一致性契约。

## 6. 资源与性能预算（DSP ≤ 60）

| 项 | 预算 |
|---|---|
| 乘法器 | N = **16** 路 int8 MAC（≈16 DSP48E1） |
| DSP | ~16~24 ≤ 60 ✓ |
| 推理延迟 | 706,752 / 16 ≈ 44,172 拍 ≈ **883 µs** @50MHz |
| II | 内层 MAC 循环 II=1（1 MAC/拍/路） |
| BRAM | 权重 ~112KB（int8）+ 激活缓冲 < 180KB（35T 有 225KB）✓ |
| LUT/FF | 远低于 35T 容量（20,800/41,600） |

- 理由：串口是瓶颈（见下），推理核 ~0.9ms 已足够；16 路 MAC 把 DSP 控制在 60 以内且留余量。

## 7. 识别时间预算与优化（评优依据）

| 波特率 | 串口传输 | 推理 | 合计 |
|---|---|---|---|
| 115200 | 791×10/115200 ≈ 68.7 ms | ~0.9 ms | ~69.6 ms |
| **1 Mbps** | 791×10/1e6 ≈ 7.9 ms | ~0.9 ms | **~8.8 ms** |

- **瓶颈在串口**（已知坑 #3），优化首选：115200 → **1 Mbps**（50MHz/50 精确分频，无误差）。
- 次要优化：推理核流水/展开（N 16→32）、精简帧（裁剪为有效区域）。
- 交付：优化前→优化后时间对比表（上位机 `bench.py` 逐帧计时）。

## 8. 分阶段落地顺序（小步闭环）

1. UART 回环（上位机发→FPGA 原样回）→ 2. 解帧（帧头/长度/CRC 校验 + 重同步）→ 3. HLS 推理核（先 csim 对拍，再综合）→ 4. 数码管/LED 回显 → 5. 全链路 + 计时。

## 9. 关键风险与对策

- C++03 约束（2018.3）；重心居中（上位机）；共阳数码管段码极性；DSP 展开度预算；HLS 全程完全权限 + loader.bat。
